# Link & Shine

PROMPT PARA LOVABLE

NOVO SISTEMA – PLAQUINHAS COM QR CODE

==================================================

1. OBJETIVO DO PROJETO

==================================================

Criar uma nova aplicação, DO ZERO, para comercialização e gerenciamento de plaquinhas físicas com QR Code exclusivo.

NÃO adaptar, reaproveitar ou depender de qualquer sistema anterior.

O produto será uma plaquinha física colocada em estabelecimentos comerciais.

O consumidor escaneia o QR Code da plaquinha e é direcionado para uma página pública personalizada daquele estabelecimento.

Essa página funcionará de forma semelhante a um Linktree, apresentando botões para diferentes canais da empresa.

Exemplos:

- Avalie no Google

- WhatsApp

- Instagram

- Site da empresa

- Outros links

O principal objetivo é facilitar que o consumidor avalie a empresa no Google e também tenha acesso rápido aos seus demais canais.

==================================================

2. PRINCÍPIO FUNDAMENTAL

==================================================

O sistema deve ser extremamente SIMPLES para o cliente.

O cliente não deve sentir que está utilizando um sistema complexo.

Fluxo ideal:

COMPROU A PLAQUINHA

        ↓

ENTRA NO SISTEMA

        ↓

LOGIN COM GOOGLE

        ↓

ESCANEIA O QR CODE

        ↓

VINCULA A PLAQUINHA

        ↓

CONFIGURA OS LINKS

        ↓

PRONTO

Toda a complexidade de controle deve ficar principalmente no painel administrativo.

Não criar cadastros ou etapas desnecessárias.

1. ADMINISTRADOR

2. VENDEDOR

3.2 VENDEDOR

------------------------------------------

==================================================

4. QR CODE

==================================================

Cada plaquinha deverá possuir um QR Code ÚNICO.

Exemplo:

Plaquinha 000001 → QR Code único A

Plaquinha 000002 → QR Code único B

Plaquinha 000003 → QR Code único C

NUNCA utilizar o mesmo QR Code em duas plaquinhas.

Cada QR Code deverá possuir um identificador único no banco de dados.

O QR Code deverá apontar para uma URL própria da plataforma.

Exemplo conceitual:

https://DOMINIO/q/ABC123

O QR Code NÃO deve apontar diretamente para o Google, Instagram ou WhatsApp.

Ele deve apontar para a plataforma, que então apresenta a página pública correspondente àquela plaquinha.

Isso permite alterar os links posteriormente sem precisar alterar ou reimprimir o QR Code.

==================================================

5. ESTOQUE DE PLAQUINHAS

O administrador deverá poder gerar lotes de plaquinhas antecipadamente.

Exemplo:

GERAR 1.000 PLAQUINHAS

O sistema deverá:

- Gerar 1.000 identificadores únicos.

- Gerar 1.000 QR Codes únicos.

- Registrar cada plaquinha no banco de dados.

- Associar cada QR Code à sua respectiva plaquinha.

- Gerar os arquivos necessários para impressão.

- Permitir controle individual de cada unidade.

Cada plaquinha deverá possuir um status.

Status sugeridos:

- DISPONÍVEL

- RESERVADA

- VENDIDA

- VINCULADA

- DOADA

- EXTRAVIADA

- BLOQUEADA

- CANCELADA

O administrador deverá conseguir visualizar:

- Total disponível.

- Total vendido.

- Total doado.

- Total extraviado.

- Total vinculado.

- Total bloqueado.

==================================================

7. VINCULAÇÃO DA PLAQUINHA

==================================================

Inicialmente todas as plaquinhas estarão disponíveis no estoque e sem cliente associado.

Fluxo:

1. Cliente entra no sistema.

2. Faz login.

3. Escaneia o QR Code da plaquinha.

4. Sistema identifica a plaquinha.

5. Sistema verifica se está disponível.

6. Cliente confirma que deseja vincular.

7. Plaquinha passa a ficar vinculada à conta do cliente.

8. Cliente configura sua página.

Depois de vinculada:

- O cliente NÃO pode desvincular.

- O cliente NÃO pode transferir para outra conta.

- Somente o administrador pode desvincular uma plaquinha.

[ SITE ]

[ OUTRO LINK ]

- Visualmente agradável.

------------------------------------------

BOTÃO GOOGLE

------------------------------------------

Deverá existir um botão padronizado:

"AVALIE NO GOOGLE"

Esse botão será configurado pela empresa através do link da página de avaliação do Google.

O sistema NÃO fará a avaliação.

O sistema apenas direcionará o consumidor para a página oficial de avaliação da empresa no Google.

Não criar sistema próprio de avaliações ou depoimentos nesta primeira versão.

==================================================

10. BLOQUEIO DA PLAQUINHA

==================================================

O cliente poderá bloquear sua própria plaquinha a qualquer momento.

Isso deverá funcionar inclusive quando a assinatura estiver vencida.

Ao bloquear:

- O QR Code deixa de disponibilizar normalmente o conteúdo da página.

- O cliente poderá desbloquear posteriormente.

O cliente poderá bloquear e desbloquear sem depender do administrador.

O administrador também poderá bloquear/desbloquear qualquer plaquinha.

==================================================

11. ASSINATURA ANUAL

==================================================

Além da venda da plaquinha, haverá uma taxa anual de manutenção do sistema.

Essa taxa será paga diretamente pelo cliente à plataforma.

O sistema deverá controlar:

- Data de início.

- Data de vencimento.

- Status.

- Valor.

- Pagamento.

- Renovação.

- Histórico.

O valor da assinatura deverá ser configurável pelo administrador.

Não deixar valores comerciais importantes fixos diretamente no código.

==================================================

12. ASSINATURA VENCIDA

==================================================

Quando a assinatura vencer:

A página pública da empresa deverá continuar acessível.

O consumidor que escanear o QR Code deverá continuar tendo acesso à página pública conforme as regras definidas.

A página poderá continuar apresentando:

- Nome da empresa.

- Site da empresa, caso exista.

Se a empresa não possuir site, não mostrar botão vazio.

Para o cliente administrador da página:

- As funções de edição ficam bloqueadas.

- Não poderá alterar os links.

- Não poderá alterar as configurações.

- Não poderá administrar a página normalmente.

Quando tentar fazer alguma alteração, mostrar uma mensagem clara:

"Para alterar as informações da sua página, é necessário renovar sua assinatura."

Disponibilizar imediatamente a opção de pagamento/renovação.

Os dados anteriores NÃO devem ser apagados.

Depois do pagamento, a conta deverá voltar ao funcionamento normal, mantendo todas as informações anteriores.

- Sistema identifica o vendedor João.

- Calcula a comissão de renovação.

- Registra a comissão.

- Disponibiliza no painel do vendedor.

28. REGRAS IMPORTANTES

==================================================

1. Cada plaquinha possui um QR Code único.

2. Duas plaquinhas nunca podem possuir o mesmo QR Code.

3. O QR Code funciona como identificador permanente da plaquinha.

4. O cliente pode vincular uma plaquinha disponível.

5. O cliente não pode desvincular sua plaquinha.

6. O cliente não pode transferir sua plaquinha.

7. Somente o administrador pode desvincular.

8. O cliente pode bloquear e desbloquear sua plaquinha.

9. O bloqueio pode ser feito mesmo com assinatura vencida.

10. A assinatura vencida bloqueia as funções administrativas de alteração.

11. Os dados da empresa não são apagados quando a assinatura vence.

12. Após o pagamento, tudo volta a funcionar com as configurações anteriores.

13. O consumidor continua podendo acessar a página pública conforme a regra de assinatura definida.

14. O botão "Avalie no Google" é padronizado.

15. O sistema não cria avaliações próprias.

16. O pagamento será integrado ao Stripe.

17. A comissão da venda e da renovação poderá possuir percentuais diferentes.

18. O administrador possui controle completo do sistema.

19. O cliente deve ter uma experiência extremamente simples.
